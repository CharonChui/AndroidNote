## 模型微调 

很多新手一遇到模型效果不好就像微调，这往往是错的第一反应。  

效果不好需要按这个顺序排查:   

- 效果不好？ 
- 先优化 Prompt
- 还不行？ 用RAG补充知识
- 还不行？ 考虑更换更强的模型
- 以上都试过扔不满足 才考虑微调  

为什么微调排最后？ 因为它的成本最高(要数据、要算力、要时间)、更新最麻烦(数据变了得重训)、且大部分问题Prompt + RAG就能解决。  

微调真正擅长解决的是:   

- 风格/格式的稳定固化: 让模型永远用某种特定语气、格式输出(Prompt反复叮嘱都不稳定时)
- 特定任务的能力强化: 某个很垂直、Prompt教不会的任务。  
- 让小模型学会大模型的某项能力: 省成本 

注意区分: 微调是教模型新的行为/风格，RAG是给模型新的知识，想让模型知道最新信息，需要用RAG而不是微调。   


### 微调的基本概念

#### 全量微调 vs LoRA

- 全量微调: 调整模型的全部参数，效果好但要巨大算力(几十上百GB显存)，个人几乎做不了。  

- LoRA(低秩适配): 只训练一小部分附加参数，冻结原模型主体。显存需求大幅降低，一张消费级显卡就能微调小模型，是个人和中小团队的主流选择。  

类比: 全量微调像重新装修整栋房子，LoRA像只换软装(家具、窗帘)---花小钱办大部分事，还能随时换回来。   

#### 微调需要什么

1. 数据: 一批输入 -> 期望输出 的高质量样本，数据质量决定一切，几百上千条精心准备的数据，往往胜过几万条脏数据。  
2. 一个基座模型: 开源的如Qwen、Llama、ChatGLM等。
3. 算力: 一张够用的GPU(本地或租云GPU)
4. 工具: 如LLaMA-Factory(新手友好，图形界面能拉起微调)、Unsloth(块且省显存)、Hugging Face PEFT库。   

#### 微调数据长什么样  

通常是这样的对话样本(JSONL格式，每行一条)

```json
{"messages": [{"role": "user", "content": "把这句话改写得更正式：这bug我搞不定"}, {"role": "assistant", "content": "此缺陷目前尚未定位到根因，需进一步排查。"}]}
```
准备几百上千条这样的样本，就是微调的核心工作。  

如果不想折腾本地环境，很多云厂商(包括模型厂商本身)提供托管微调服务:    
你上传数据 -> 平台帮你训 -> 给你一个微调后的模型接口调用。  


### 私有化部署：把模型跑在自己机器上

为什么要私有化部署?   

- 数据安全/合规: 敏感数据不能发给第三方API
- 成本: 高频调用时，自己部署开源模型可能比调API便宜
- 可控/离线: 不依赖外部服务，可断网运行。 

代价: 你要自己搞定GPU、运维、性能优化 - 比调API复杂得多。  


### 新手友好的部署工具

- Ollama: 一行命令就能在本地跑开源模型，Ollama提供OpenAI兼容接口，所以只要把base_url换成本地地址就能切换到本地模型
- vLLM: 生产级高性能推理引擎，追求高并发、低延时用，比Ollama复杂，但块很多
- LM Studio: 带图形界面，适合桌面端长线 

### 部署要关心的概念

- 量化(Quantization): 把模型参数从高精度压成低精度(如FP16 -> INT4)，大幅降低显存占用，代价是轻微精度损失。让大模型能塞进小显卡的关键技术。你会看到模型名带Q4、INT8之类标记，就是量化版本。  

- 显存需求: 模型大小 ≈ 参数量 * 每参数字节数。 7B模型FP16大约要14GB显存，INT4量化后约 4~5GB。选模型前先算算你的显卡够不够。
